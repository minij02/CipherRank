# 1. 서론

## 1.1 연구 배경

분산 신뢰 시스템에서 한 참여자의 신뢰도를 정량화하는 표준적인 방법은 노드 간 평가 그래프 위에서 PageRank 를 계산하는 것이다. 그러나 평가 대상을 평문으로 받는 일반적 구현은 *누가 누구를 조회했는가* 가 그 자체로 메타데이터로 누설된다는 한계를 가진다. 본 보고서는 SNAP 의 Bitcoin OTC 신뢰 그래프 위에서 동형암호 기반 사적 정보 검색 (Private Information Retrieval, 이하 PIR) 과 동형 PageRank 를 결합한 시스템 *CipherRank* 의 알고리즘 구성을 기술한다.

CipherRank 의 작동 원리는 다음과 같이 요약된다. 클라이언트는 평가 대상 지갑의 전역 인덱스를 one-hot 벡터로 변환하여 CKKS 동형암호로 암호화한다. 서버는 인덱스의 정체를 알지 못한 채, 사전에 캐싱된 행렬 대각선들과의 동형 곱을 통해 해당 인덱스 열의 trust 분포를 추출한다. 이렇게 얻은 부분 그래프 위에서 동형 PageRank 의 멱법 반복을 수행하고, 결과 점수를 임계값과 비교하여 `APPROVED` 또는 `REJECTED` 의 판정을 산출한다.

본 보고서의 범위는 알고리즘과 구현의 형식적 기술에 한정한다. 시스템 수준의 보안 분석과 성능 벤치마크는 별도의 설계 명세 (`docs/superpowers/specs/`) 를 참조한다.

## 1.2 보고서의 기여

본 보고서가 정리하는 사항은 다음 세 가지이다.

(i) 1-홉 및 2-홉 신뢰의 의미 모델 — 가중 계수 β₁, β₂ 와 임계 가지치기 θ — 을 도입한 희소 그래프 전처리 절차의 형식적 기술 (§2).

(ii) Halevi-Shoup 의 대각선 분해를 비대칭 Baby-Step Giant-Step (BSGS) 알고리즘으로 확장하여 동형 행렬-벡터 곱의 회전 비용을 O(N) 에서 O(√N) 으로 축소하는 방법 (§3).

(iii) 단일 당사자 가정 하에서 매 반복마다 복호 후 재암호화를 수행하는 동형 PageRank 의 구성과 그 수치적 안정성에 대한 분석 (§4).

이에 더해 §5 에서는 구현 과정에서 드러난 엣지 케이스, 부동소수점 결정성 보장, 그리고 SEAL 라이브러리의 transparent ciphertext 예외와 같은 구체적 함정을 정리한다.

각 장의 말미에는 N = 4 의 가상 그래프를 사용한 손 계산 예제가 부록으로 부속된다. 동일한 예제가 §2 부터 §5 까지 일관되게 사용되므로, 알고리즘의 각 단계가 어떻게 맞물려 작동하는지를 직접 검산할 수 있다.

## 1.3 표기와 파라미터

본 보고서 전반에 걸쳐 사용하는 기호와 그 기본값을 다음 표에 정리한다.

| 기호 | 의미 | 기본값 / 결정 위치 |
|---|---|---|
| N | 빈도 상위 N 개 지갑으로 구성된 전역 인덱스 공간 | 256 (`-g`) |
| n | Phase 4 가 선택하는 부분 그래프의 차원 | 64 (`-s`) |
| K | 평가 대상을 SIMD 청크에 나누어 담은 결과의 청크 수 | 자동 계산 (`CipherRank.cpp:408`) |
| P | OpenMP 스레드 수 | 4 |
| β₁, β₂ | 1-홉 및 2-홉 가중치 | 1.0 / 0.30 |
| θ | 2-홉 전파를 차단하는 1-홉 임계값 | 0.05 |
| m₁, m₂ | 비대칭 BSGS 의 baby step / giant step 크기 | `FindOptimalAsymmetricBSGS` |
| α | PageRank damping factor | 0.85 |
| I | 멱법 반복 횟수 | 10 |
| scale | CKKS 인코딩 스케일 | 2⁴⁵ |
| coeff_modulus | CKKS 모듈러스 사슬 (비트) | {60, 45, 45, 60} |

CKKS 다항식 차수 `poly_modulus_degree` 는 N 의 함수로 자동 결정되며, 최소 2N 슬롯을 확보하기 위해 N = 256 의 경우 8192, N = 2048 의 경우 16384 의 값을 가진다.

한 SIMD 청크는 슬롯 공간에서 2N 개의 연속된 슬롯을 차지한다. 이 중 앞쪽 N 슬롯은 유효 영역, 뒤쪽 N 슬롯은 BSGS 회전이 청크 경계를 침범하지 못하도록 두는 패딩 영역이다 (자세한 분석은 §3.5). 한 청크에 담을 수 있는 평가 대상의 수는 `batch_size = slot_count / 2N` 으로 결정되며, 예를 들어 N = 1024, poly = 8192 의 경우 batch_size = 2 가 된다.

## 1.4 입력 데이터

원본 데이터셋은 SNAP 의 `soc-sign-bitcoinotc.csv` 이다. 한 행은 (송신자 지갑 ID, 수신자 지갑 ID, 가중치, 시각) 의 네 필드로 구성되며, 가중치는 −10 에서 +10 사이의 정수, 시각은 유닉스 시각이다. 양수는 신뢰, 음수는 불신을 의미한다.

본 시스템의 파서 (`CipherRank.cpp:376`) 는 가중치가 2 이상인 행만 수용한다. 그 결과 원본 35,592 행 중 11,981 행이 통과하며, 등장하는 노드 수는 3,302 개로 정리된다. 평균 출차수 d̄ = E/V ≈ 3.628 로, 이는 전형적인 희소 사회 그래프의 분포에 부합한다.

음수 가중치를 갖는 간선이 원본에 분명히 존재함에도 초기 필터링 단계에서 모두 제거되는 점은 의미 모델 전체에 비-사소한 영향을 미친다. 불신 신호의 완전한 소실이 자연 sybil 검출 능력에 어떤 영향을 주는지는 §5.1.1 에서 별도로 다룬다.

## 1.5 위협 모델

본 시스템에서 서버가 *모른다* 고 가정하는 정보는 다음 두 가지이다.

(a) 클라이언트가 어느 지갑을 평가 대상으로 선택하였는가. one-hot 인코딩의 1 위치는 CKKS 암호문 내부에서만 의미가 정의되며, 서버는 ciphertext 의 평문에 접근할 수 없다.

(b) 평가 결과 점수의 실수 값. Phase 5 의 출력 역시 ciphertext 형태로 유지된다.

서버가 보유하는 정보는 전체 그래프 (BitcoinOTC csv 자체는 공개 데이터로 간주), 청크 수 K, BSGS 파라미터 (m₁, m₂), 그리고 Galois key step 집합이다. 이들 정보는 모두 N 의 함수이며 평가 대상에 의존하지 않는다. 따라서 BSGS 가 평가 대상과 무관하게 동일한 수의 회전을 동일한 step 집합으로 수행함이 보장되며, 결과적으로 wall-clock 측정값 또한 평가 대상에 *대해 무관* 함이 시스템 수준에서 성립한다.

다만 본 구현은 §4.5 에서 다루듯 멱법 반복의 매 단계마다 복호 후 재암호화를 수행하므로, 실질적으로 서버가 비밀키를 소유한다. 이는 PIR 의 엄격한 위협 모델에 부합하지 않으며, 본 보고서의 측정값은 *단일 당사자 측정 환경* 에서의 알고리즘 수준 비교로 한정 해석되어야 한다. 진정한 PIR 보장으로의 확장 경로는 (i) Phase 5 의 복호-재암호 루프를 동형 정규화로 대체, (ii) 반복 횟수를 CKKS useful depth 내로 축소, (iii) bootstrapping 도입의 세 가지이며, 모두 본 보고서의 범위를 벗어난다.

## 1.6 예제 그래프

본 보고서의 각 장은 그 끝에 N = 4 의 가상 그래프를 사용한 손 계산 예제를 부록으로 포함한다. 동일한 예제가 §2 부터 §5 까지 일관되게 사용되므로 본 절에서 미리 정의한다.

다음 6 행으로 구성된 가상의 csv 를 입력으로 가정한다.

```
10,20,4,T
10,30,3,T
20,30,5,T
30,40,2,T
40,10,3,T
30,10,4,T
```

모든 시각이 동일한 값 T (= `maxTime`) 로 설정되어 시간 감쇠 계수가 1.0 으로 고정되며, 이에 따라 raw 가중치가 변형 없이 보존된다. 6 행 모두 `parts[2] >= 2` 필터를 통과한다.

빈도 카운트는 wallet 10 과 30 이 각각 4 회, wallet 20 과 40 이 각각 2 회로 집계된다. nGlobal = 4 로 두면 네 노드 모두 전역 인덱스를 부여받는다. 빈도 동률 (10 과 30, 20 과 40) 사이의 정확한 순서는 unordered_map 의 이터레이션 순서에 의존하나 (§5.6 참조), 본 예제는 다음의 매핑을 고정 가정한다.

```
wallet 10 → globalIdx 0
wallet 30 → globalIdx 1
wallet 20 → globalIdx 2
wallet 40 → globalIdx 3
```

평가 대상은 wallet 30 (= 전역 인덱스 1) 한 명으로 두며, 단일 청크 · batch_size = 1 · slot_count = 2N = 8 의 가장 단순한 시나리오를 가정한다. 부분 그래프의 차원은 부록의 §4.A 에서 nSub = 3 으로 둔다.

## 1.7 보고서 구성

이후의 구성은 다음과 같다.

§2 는 BitcoinOTC csv 로부터 1-홉 가중치 행렬 M_pub 과 BSGS 용 대각선 평문 리스트 BsgsDiag 를 구성하는 Phase 1 의 절차를 다룬다. §3 은 클라이언트로부터 수신한 one-hot 암호문에 대해 Halevi-Shoup 의 대각선 분해와 비대칭 BSGS 를 적용하여 부분 그래프를 동형으로 추출하는 Phase 3 의 절차를 다룬다. §4 는 부분 그래프 인덱스 결정 (Phase 4), 동형 PageRank 멱법 반복 (Phase 5), 그리고 임계값 비교에 의한 최종 판정 (Phase 6) 을 다룬다. §5 는 구현 과정에서 드러난 엣지 케이스, 수치적 안정성, 그리고 단일 당사자 가정의 한계를 정리한다.

각 장의 부록 (§2.A, §3.A, §4.A, §5.A) 에는 §1.6 의 N = 4 예제 위에서 본문 절차가 산출하는 수치를 손 계산으로 검증한 결과를 수록한다.
