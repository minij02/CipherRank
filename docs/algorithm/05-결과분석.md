# 5. 실험 결과 및 분석

본 장은 §2 부터 §4 까지 기술한 알고리즘 구성을 실제 BitcoinOTC 데이터셋 위에서 실행한 측정 결과를 정리한다. 측정 환경은 §5.1 에 명시하고, 단일 MVB (Minimum Viable Benchmark) 실행은 §5.2 에서 stdout 까지 그대로 수록한다. 이어서 §5.3 의 모드별 wall-clock 비교, §5.4 의 OpenMP 스케일링, §5.5 의 β·θ 의미 모델 sweep, §5.6 부터 §5.7 까지의 sybil 검출 평가, §5.8 의 정밀도 분석, 그리고 §5.9 의 N = 4096 대형 그래프 데모를 차례로 다룬다. 구현상의 함정과 위협 모델의 한계에 대한 별도의 논의는 §6 에서 이어진다.

(i) 단계별 wall-clock 의 분포는 P1 (22 %), P3 (11 %), P5+P6 (55 %) 로 PageRank 멱법 반복이 가장 큰 비중을 차지한다. P2 와 P4 는 합쳐도 1 % 미만이다.

(iv) Galois key step set 의 크기 33 은 BSGS 가 도입되지 않은 baseline 의 256 (= N) 대비 약 8 배 축소된 값이다. 이는 §5.3 의 Phase 3 wall-clock 감축의 일관된 산출 메커니즘이다.

(v) 4 개 wallet 모두에서 FHE Engine Score 와 Plaintext Score 의 Precision Error 가 정확히 0 으로 측정되었다. CKKS 노이즈가 소수점 6 자리 이내에서는 결과에 영향을 주지 않음을 보인다. 이 성질은 §5.8 에서 sweep 전반으로 확장되어 검증된다.

## 5.3 모드별 wall-clock 비교

`coarse_sweep.json` 의 3 회 반복 평균 (P = 4) 으로부터 main / A1 / A2 / B 네 모드의 단계별 wall-clock 을 정리하면 다음과 같다.

### 5.3.1 N = 256

| Mode | Phase 1 | Phase 3 | Phase 5 + 6 | Total |
|---|---:|---:|---:|---:|
| main | 0.742 s | 0.908 s | 2.079 s | 3.821 s |
| A1   | 0.668 s | 0.121 s | 0.611 s | 2.221 s |
| A2   | 0.669 s | 0.916 s | 2.072 s | 3.747 s |
| **B**    | **0.225 s** | **0.121 s** | **0.614 s** | **1.078 s** |

main → B 비율: Total 3.55 ×, Phase 1 3.30 ×, Phase 3 7.50 ×, Phase 5+6 3.39 ×.

A1 (BSGS 만) 도입으로 Phase 3 의 7.5 × 단축이 확보되며, 이는 §3.3 에서 분석한 회전 횟수 N → 2√N − 2 의 직접적 귀결이다. A2 (β·θ 가지치기 만) 의 Phase 3 wall-clock 은 main 과 거의 동일한데, sparseDiag 의 D_sparse 가 N = 256 의 작은 차원에서 256 / 256 으로 sparsity 가 0 이기 때문이다. B 통합에서 Phase 1 의 추가 단축은 sparse 표현이 BSGS 평문 인코딩 단계의 메모리 접근을 정렬화한 효과로 해석된다.

### 5.3.2 N = 1024

| Mode | Phase 1 | Phase 3 | Phase 5 + 6 | Total |
|---|---:|---:|---:|---:|
| main | 7.678 s | 21.489 s | 48.914 s | 78.199 s |
| A1   | 2.564 s | 0.941 s  | 4.512 s  | 11.286 s |
| A2   | 2.556 s | 21.546 s | 48.949 s | 73.170 s |
| **B**    | **0.800 s** | **1.012 s**  | **4.574 s**  | **6.648 s**  |

main → B 비율: Total 11.76 ×, Phase 1 9.60 ×, Phase 3 21.23 ×, Phase 5+6 10.69 ×.

N 이 4 배 증가했을 때 main 의 wall-clock 은 약 20 배 증가 (3.82 → 78.2 s) 하는 반면 B 는 약 6 배 증가 (1.08 → 6.65 s) 에 그친다. 이는 baseline 의 O(N) 회전과 BSGS 의 O(√N) 회전의 점근적 차이가 N 의 증가에 따라 더 크게 드러남을 보인다.

### 5.3.3 OMP 분배의 한계 — phase 3 비율

Phase 3 의 main → B 비율 (N = 1024 에서 21.23 ×) 은 회전 횟수 비율 ≈ N / (2√N − 2) = 1024 / 62 ≈ 16.5 보다 약간 크다. 이 초과분은 OMP 청크 분배가 추가로 기여하는 효과로, §3.6 의 청크별 독립성에 기인한다. 다만 OMP 의 실제 효과는 §5.4 에서 보이듯 본 환경에서 양의 스케일링을 산출하지 못하므로, 위 21 × 의 main → B 비율은 회전 수 감축이 거의 단독으로 설명한다고 해석된다.

## 5.4 OpenMP 스케일링

`omp_axis.json` 의 B 모드 N = 1024 측정 결과는 다음과 같다.

| OMP threads | Phase 1 | Phase 3 | Phase 5 + 6 | Total |
|---:|---:|---:|---:|---:|
| 1 | 0.778 s | 0.933 s | 4.378 s | 6.352 s |
| 2 | 0.808 s | 0.987 s | 4.528 s | 6.585 s |
| 4 | 0.817 s | 1.009 s | 4.591 s | 6.678 s |
| 8 | 0.816 s | 1.027 s | 4.637 s | 6.741 s |

본 데이터는 *anti-scaling* 의 명백한 양상을 보인다. 단일 스레드 (OMP = 1) 에서 가장 짧은 6.35 s 를 산출하며, OMP 가 증가할수록 wall-clock 이 *증가* 한다. 6.35 → 6.74 s 의 6.1 % 증가는 통계적으로 유의한 폭이며, 본 환경에서 OMP 도입이 오히려 부담으로 작용함을 시사한다.

본 anti-scaling 의 원인은 두 가지로 분해된다. 첫째, 본 머신의 물리 코어 수가 4 이므로 OMP = 8 은 oversubscription 으로 분류되며, thread context switching 비용이 이득을 상쇄한다. 둘째, N = 1024 의 5 개 청크 (`num_chunks ≈ N / 256 = 4–5`) 를 분배할 때 청크 수 자체가 작아 thread-local Evaluator 생성 비용이 회수되지 않는다. 더 큰 청크 수 (`num_targets ≥ 64`) 환경에서만 OMP 가 양의 효과를 산출할 것으로 예상되며, 본 시스템의 기본 측정 시나리오에는 부합하지 않는다.

본 결과는 §6.8.2 의 OMP 한계 논의와 정합한다.

## 5.5 β·θ 의미 모델 sweep

`fine_grid_full.json` 의 9 cell sweep (N = 1024, B 모드, 3 반복 평균) 결과를 정리한다.

| β₂ \ θ | 0.00 | 0.05 | 0.50 |
|---:|---:|---:|---:|
| 0.0 | 6.183 s | 6.383 s | 6.491 s |
| 0.3 | 6.679 s | 6.614 s | 6.634 s |
| 1.0 | 388.769 s | **687.505 s** | 7.130 s |

9 cell 중 7 cell 의 wall-clock 은 6.18 – 7.13 s 의 좁은 범위에 집중되어 β₂, θ 의 변화가 wall-clock 에 사실상 영향을 주지 않음을 보인다. 그러나 두 cell — (β₂ = 1.0, θ = 0.00) 의 388.8 s 와 (β₂ = 1.0, θ = 0.05) 의 687.5 s — 는 정상 값의 약 60 배와 110 배의 극단적 outlier 로 나타난다.

(β₂ = 1.0, θ ≤ 0.05) 조건은 모든 2-홉 간선이 가지치기 없이 1.0 배 가중치로 전파되는 의미 모델에 해당한다. 이 조건에서 sparseDiag 의 D_sparse 가 사실상 N 에 근접하여 BSGS 의 평문 곱 횟수가 최대치가 되며, 동시에 Phase 5 의 부분 행렬에 *모든 노드* 가 강한 가중치로 연결되어 멱법 반복의 매 단계에서 ciphertext 의 노이즈 부하가 평소보다 증가한다. 다만 정상 cell 의 7 s 수준 대비 60 – 110 배의 wall-clock 차이는 알고리즘적 비용 만으로 설명되기 어려우며, 본 측정의 sustained-load 환경에서 발생한 thermal artifact 의 영향이 혼입되어 있을 가능성이 높다. 본 사례는 §6.8.1 에서 별도로 다룬다.

(β₂ = 1.0, θ = 0.50) 의 7.13 s 는 θ 가 모든 1-홉 약신뢰 (raw weight ≤ 1.7 환산) 를 제거하여 D_sparse 가 다시 정상 수준으로 떨어진 결과로 해석된다.

## 5.6 자연 sybil 검출 — BitcoinOTC −10 평점 노드

`r8_sybil.json` 은 BitcoinOTC 원본 csv 에서 다수의 −10 평점을 받은 18 개 후보 wallet 에 대한 5 모드 교차 측정 결과이다 (N = 1024, P = 4). 단, §1.4 의 가중치 필터 (≥ 2) 로 인해 음수 평점 자체는 평가에 직접 반영되지 않으며, 본 검증의 목적은 "외부에서 자연 sybil 으로 식별된 노드를 본 시스템이 REJECT 로 판정하는가" 이다.

| Mode | APPROVED | REJECTED | max \|fhe − plain\| | Total time |
|---|---:|---:|---:|---:|
| main | 8 | 10 | 0.000e+00 | 134.60 s |
| A1   | 8 | 10 | 0.000e+00 | 14.08 s |
| A2   | 8 | 10 | 0.000e+00 | 129.78 s |
| **B**    | **8** | **10** | **0.000e+00** | **9.39 s** |
| B-C2 | 8 | 10 | 0.000e+00 | 9.65 s |

5 모드 모두 동일한 판정 분포 (8 APPROVED / 10 REJECTED) 를 산출하며, 모든 18 개 wallet 에 대해 FHE 점수와 평문 점수가 소수점 자리에서 완전히 일치한다 (max \|fhe − plain\| = 0). 이는 BSGS 와 sparse + Q5 + Q7 의 통합이 판정의 *의미* 를 보존함을 직접 보이는 결과이며, 본 보고서의 핵심 등가성 가정의 실측 증거에 해당한다.

wall-clock 측면에서 B 모드의 9.39 s 는 main 의 134.60 s 대비 14.3 × 단축을 산출한다. N = 1024, 18 wallet 의 시나리오에서 sybil 검출의 실용성을 회복시키는 폭의 단축으로 해석된다.

REJECT 로 판정된 10 wallet 의 점수는 모두 0.000000 으로 보고된다. 이는 자연 sybil 후보들이 가중치 필터 통과 후의 인접 리스트에서 인입 trust 자체가 0 인 노드임을 의미한다. 본 결과는 §1.4 에서 명시한 가중치 필터의 가시적 부수 효과이며, sybil 검출의 의미 모델 정렬에 부합한다.

## 5.7 합성 sybil 검출

`r8_synthetic_sybil.json` 은 BitcoinOTC 원본에 50 개의 합성 sybil 노드를 인공적으로 주입한 데이터셋 (`soc-sign-bitcoinotc-synthetic.csv`) 위에서의 측정 결과이다. 합성 sybil 은 §5.1.1 의 가중치 필터 제약을 만족하기 위해 sybil-to-sybil 평점을 5, 외부 평점을 2 로 설계되어 있다.

| Mode | APPROVED | REJECTED | Total time |
|---|---:|---:|---:|
| **B**    | **0 / 50** | **50 / 50** | **20.69 s** |
| B-C2 | 0 / 50 | 50 / 50 | 21.96 s |

50 개 합성 sybil 모두에 대해 B 와 B-C2 가 일관되게 REJECT 판정을 산출하며, TPR (True Positive Rate) = 100 % 가 측정된다. 평균 wall-clock 약 0.4 s/wallet 의 처리 속도는 본 시스템의 합성 sybil 식별이 실용적 규모로 작동함을 보인다.

위 결과는 합성 sybil 시나리오의 한 변종에 한정된 측정이며, sybil 이 실제 trust hub 와도 약하게 연결된 위장 sybil 모델 (hub-trust-mixed) 의 평가는 본 측정 범위 외이다. 후속 작업으로의 분리는 §6.9 에서 다룬다.

## 5.8 정밀도 분석 — FHE vs 평문

§5.2 의 단발 측정과 §5.6 의 자연 sybil 검증에 이어, 본 보고서가 인용하는 *모든* sweep cell (총 113 cell 의 verdict 출력) 에 대한 Precision Error = \|fheScore − plainScore\| 의 분포를 정리한다.

| 데이터셋 | 측정된 verdict 수 | max Precision Error | 발생 cell 수 |
|---|---:|---:|---:|
| coarse_sweep.json (main vs A1/A2/B, N = 256·1024) | 24 cells × 4 wallets = 96 | 0.000e+00 | 0 |
| fine_grid_full.json (β·θ sweep, N = 1024) | 27 cells × 4 wallets = 108 | 0.000e+00 | 0 |
| r8_sybil.json (자연 sybil, 5 mode × 18 wallets) | 90 | 0.000e+00 | 0 |
| r8_synthetic_sybil.json (합성 sybil, 2 mode × 50 wallets) | 100 | 0.000e+00 | 0 |
| demo_4096.json (N = 4096) | 2 cells × 4 wallets = 8 | 0.000e+00 | 0 |

본 시스템의 모든 측정에서 FHE 결과와 평문 ground truth 사이의 차이가 소수점 6 자리 이내에서 정확히 0 으로 측정된다. 이는 두 가지 사실의 결합적 귀결이다.

첫째, §4.5 의 매 반복 후 복호 후 재암호화 루프가 CKKS 노이즈를 매 반복마다 0 으로 초기화하므로 노이즈의 누적이 평가 단계까지 도달하지 않는다.

둘째, §4.7 의 음수 절단과 sum-to-1 재정규화가 ciphertext 의 미세 오차를 매 반복 후 제거한다.

본 결과는 본 시스템의 단일 당사자 측정 가정 하에서 CKKS 노이즈가 사실상 의사 결정에 영향을 주지 않음을 직접 보인다. 진정한 PIR 위협 모델 (서버가 비밀키를 보유하지 않음) 로의 확장에서는 본 절의 결론이 그대로 이전되지 않으며, 동형 정규화 또는 bootstrapping 도입에 따른 별도의 분석이 요구된다 (§6.7 참조).

## 5.9 대형 그래프 데모 — N = 4096

`demo_4096.json` 은 본 시스템의 N 확장성을 보이기 위한 단발 측정이다. main 모드는 본 N 에서 실용적 시간 내에 종료되지 않으므로 A1 (BSGS 단독) 과 B 의 비교만 수록한다.

| Mode | Phase 1 | Phase 3 | Phase 5 + 6 | Total |
|---|---:|---:|---:|---:|
| A1   | 21.86 s | 14.85 s | 15.83 s | 79.22 s |
| **B**    | **6.86 s**  | **13.28 s** | **15.79 s** | **36.96 s** |

A1 → B 의 추가 단축은 주로 Phase 1 에서 발생한다 (21.86 → 6.86 s, 3.19 ×). 이는 N = 4096 의 큰 차원에서 sparse + Q7 패딩의 메모리 효율 효과가 두드러짐을 보인다. Phase 3 의 단축 (14.85 → 13.28 s, 1.12 ×) 은 N 이 증가할수록 BSGS 가 이미 거의 모든 회전 비용을 제거한 상태에서 추가 최적화의 여지가 작음을 시사한다.

N = 4096 에서의 B 모드 36.96 s 는 18 wallet 환경의 자연 sybil 검출 (§5.6, N = 1024) 대비 약 3.9 × 의 시간으로, N 의 4 배 증가에 비해 sub-linear 의 증가율을 보인다. 본 결과는 본 시스템이 N = 4096 의 대형 그래프 환경에서도 실용적 wall-clock 으로 작동함을 보인다.

## 5.10 종합 정리

본 장의 측정 결과를 종합하면 다음 다섯 가지 결론이 도출된다.

(i) **wall-clock 단축의 정량적 검증.** main → B 의 총 wall-clock 비율은 N = 256 에서 3.55 ×, N = 1024 에서 11.76 × 이며, Phase 3 단독 비율은 각각 7.5 × 와 21.2 × 이다. 후자는 §3.3 의 이론적 회전 수 감축비 (16.5 × 수준) 와 일치하는 폭이다.

(ii) **의미 보존의 직접 확인.** §5.6 의 5 모드 교차 측정에서 18 wallet 모두 판정이 일치하며, §5.8 의 모든 sweep cell 에서 Precision Error = 0 이 측정된다. 본 시스템의 알고리즘 등가성 가정이 실측 수준에서 보존됨을 보인다.

(iii) **합성 sybil 검출의 실용성.** §5.7 의 50 개 합성 sybil 에 대한 TPR = 100 % 와 평균 0.4 s / wallet 의 처리 속도는 sybil 검출 시나리오에서의 실용적 작동을 보인다.

(iv) **OpenMP 의 한계.** §5.4 의 anti-scaling 측정은 본 환경에서 OMP 의 도입이 양의 효과를 산출하지 못함을 보이며, 청크 수가 증가하는 시나리오에서만 OMP 가 의미를 가짐을 시사한다.

(v) **β·θ 의미 모델의 wall-clock 영향.** §5.5 의 9 cell sweep 중 7 cell 은 6 – 7 s 의 좁은 범위에 머무나, (β₂ = 1.0, θ ≤ 0.05) 의 두 cell 은 60 – 110 배의 극단적 outlier 를 산출한다. 본 outlier 는 알고리즘적 비용과 thermal artifact 의 결합으로 해석되며, §6.8.1 에서 별도로 다룬다.

본 장의 측정값은 모두 단일 머신의 단일 시점 환경에서 산출된 *honest reporting* 의 결과이며, 측정 환경의 변화에 따른 절대값의 변동 가능성은 §6.8 에서 별도로 명시한다.
